# 视频压缩说明

[文档目录](README.md)

[返回使用说明](usage.md#视频压缩)

压缩以保留可感知画质为目标，不默认缩放或降低帧率。视频重新编码是有损处理，不能同时保证任意视频大幅缩小、完全不损失画质和快速完成。已经充分压缩的视频可能收益很小，结果不比原件小时不会保存。

## 选择模式

- 高效压缩：H.265，自动显卡优先，适合日常批量处理。先选清晰优先，检查结果后再考虑均衡。
- 兼容优先：H.264，自动显卡优先，适合旧设备、浏览器和分享。10-bit SDR 转为 8-bit，可能减少渐变细节。
- 精细压缩：CPU 的 x265 slow 预设，愿意等待时使用。通常有更好的压缩效率空间，但不保证每个文件都比显卡结果更小。

三种模式均输出 MP4。H.265 播放能力依赖播放器、设备及系统解码组件；需要广泛播放时选择兼容模式。GPU 加速主要改善速度和 CPU 占用，不能据此认定画质或体积优于 CPU。

## 加速和失败回退

源视频始终使用软件解码，然后交给所选编码器。这允许显卡无法直接解码的源格式仍使用显卡编码；CPU 仍会有占用，任务管理器应关注 Video Encode 引擎。

自动模式依次尝试 NVIDIA NVENC、Intel QSV、AMD AMF，最后使用 CPU 的 x264 / x265。指定某一品牌时只尝试该品牌和 CPU；精细模式始终使用 CPU。运行时读取 FFmpeg 编码器列表，再执行短时试编码，不能仅凭显卡名称认定可用。同一批次按编码器和输出位深复用硬件检测结果。

实际文件处理失败后，会清理未完成输出再重试。复制 AAC 导致兼容问题时，尝试重新编码音轨；仍失败则换编码设备，直至 CPU。回退保持所选 H.264 / H.265，不会静默切换编码格式。软件解码、音频转换和 CPU 回退仍无法处理的损坏文件会报告失败，其他文件继续处理。

NVIDIA / Intel 可在对应硬件上运行集成测试。AMD 参数已接入，但需要在 AMD 设备上进一步验证；失败可回退 CPU。无需 CUDA 开发工具包，硬件编码仍依赖可用的显卡驱动。

## 画质与媒体内容

界面清晰、均衡、体积优先分别使用 18、23、28 的画质基准值。H.265 在该基准上加 2；NVIDIA 的 CQ 再加 3；Intel 使用 ICQ，AMD 使用 CQP，CPU 使用 CRF。这是便于使用的初始映射，不是相同画质的数学换算或质量保证。自定义基准值 0 固定使用 CPU 最高画质编码，通常无法减小体积。

- NVIDIA：p6 / hq、质量目标 VBR、前瞻分析和空间自适应量化。
- Intel：slow / ICQ。
- AMD：quality / CQP。
- CPU：medium，精细模式使用 slow。

默认不缩放、不修改帧率，保留可变帧率时间戳。旋转画面按显示方向输出；奇数尺寸在边缘补最多 1 像素，便于 4:2:0 编码。高效、精细模式对 10-bit SDR 使用 10-bit 输出，8-bit 源维持 8-bit；更高位深源会转换为 10-bit。RGB / 4:4:4 等源会转换为 4:2:0，不能视为像素无损。

AAC 音轨优先复制；其他音频转换为 AAC，双声道及以下使用 192 kbps，多声道使用 384 kbps，不主动混为双声道。保留全部音轨和章节，内嵌字幕、封面和附件不输出，原文件保留。

## HDR 视频

“HDR 视频”按工作区记忆，有以下处理方式：

| 选择 | 输出与用途 |
| --- | --- |
| 保留 HDR（默认） | HLG / HDR10 输出 H.265 10-bit，保留亮度曲线、色域、已知色彩范围和静态母版/亮度元数据。即使选择 H.264，也只对 HDR 文件改用 H.265；普通文件保持原设置。 |
| 转为普通 SDR | 通过线性光浮点处理与 Mobius 色调映射，转换为 BT.709 8-bit，适合普通屏幕和兼容性要求高的播放器。使用当前所选 H.264 / H.265；观感会变化，先抽查结果。 |
| 保留 HLG 基层 | 对带 Dolby Vision 信息的 HLG 视频保留 HLG 10-bit、主动移除杜比动态信息。会失去杜比动态显示效果；仅在接受此变化时选用。普通 HLG / HDR10 仍按保留 HDR 处理。 |
| 跳过 HDR | 保留原片，仅处理 SDR 文件。 |

保留 HDR 时，HLG / 无静态元数据的 PQ 可使用显卡编码；带有母版显示或内容亮度信息时使用 CPU x265 显式写回并校验元数据。转 SDR 的滤镜运行在 CPU，显卡只加速编码，因此不保证和普通视频一样快。需要随包完整版 FFmpeg 的 zscale、tonemap、sidedata 滤镜。

默认保留模式遇到 Dolby Vision、HDR10+ 等动态 HDR 会跳过；只有带 HLG 兼容基层的 Dolby Vision 可通过上述显式选项转换。其他动态 HDR 暂不转换；色彩信息不完整或高于 10-bit 的 HDR 也保留原片。扫描读取开头最多 32 个视频包对应的帧以识别 HDR 元数据，不能保证发现仅在后续帧出现的动态信息或错误标注。成品会额外验证色彩信息和已识别的静态 HDR 元数据；这些检查不代替实际屏幕上的视觉抽查。

## 输出保护与进度

正常 AAC 音轨优先直接复制。若音轨复制遇到不兼容，会保留当前视频编码器并重试 AAC；若明确报音轨 DTS 倒退，则重编码并使用 `aresample=async=1` 补偿时间戳衔接，异常处可能补静音或裁去重叠音频，不强制把音轨起点归零。只有视频编码仍失败时才换设备，已确认的音频修复会沿用。命令预览也提供对应备用命令；建议抽听异常位置。[FFmpeg 音频补偿说明](https://ffmpeg.org/ffmpeg-resampler.html#Resampler-Options)

转换在独立临时目录完成，验证输出编码、画面尺寸、时长、位深及音轨数量，再按体积决定是否保存。它不是逐帧视觉质量检测，仍建议先抽查少量结果。原视频及已有目标不覆盖，取消任务会清理当前临时结果。

当前文件的进度约每 10 秒更新，显示编码速度和估计剩余时间；进度来自媒体时间戳，封装和复制成品还需要时间。批次进度仍按已处理文件数统计。

最小体积和最小源码率仅为扫描过滤条件，不是输出码率限制；设为 0 可处理所有支持文件。视频参数按工作区保存，升级旧配置时保留 H.264 模式与原画质值。

参数依据：[FFmpeg 编码器文档](https://ffmpeg.org/ffmpeg-codecs.html)、[NVIDIA FFmpeg 高画质转码说明](https://docs.nvidia.com/video-technologies/video-codec-sdk/13.0/ffmpeg-with-nvidia-gpu/index.html)、[x265 参数说明](https://x265.readthedocs.io/en/master/cli.html)。

旧版 FFmpeg 自动检测命令参数能力：不支持 `fps_mode` 时使用 `vsync 0`，不支持 `stats_period` 时省略；旧版 NVIDIA 编码器使用其支持的预设及 AQ 参数名。参数解析失败直接报告，只有明确音频相关错误才尝试重新编码音轨。旧 FFmpeg 的 NVENC SDK 仍可能不兼容新显卡驱动，此时使用 CPU；建议优先选择随包的 FFmpeg 与 FFprobe。

## 复制单文件压缩命令

扫描后，在预览的目标路径下展开“查看 / 复制压缩命令”。程序按当前设置检查编码器，提供可用的主编码命令、CPU 等备用命令；复制后粘贴到 Windows PowerShell 执行。命令与工具箱共用参数生成逻辑，包括旧版 FFmpeg 参数适配、音轨、位深和画质设置。命令使用预览中的输出路径，自动创建目录，以 `-n` 防止覆盖已有文件；路径及参数均按 PowerShell 字符串转义。

独立命令只运行一次所选 FFmpeg 编码，不包含工具箱的临时文件发布、自动回退、成品完整性验证或“没有变小就丢弃”的处理。备用命令需要手动选择；输出失败或变大时请自行检查清理。预览中有冲突或跳过原因的项目不生成命令。修改参数后请重新扫描。

HLG 兼容基层依据：[Dolby 官方说明](https://professionalsupport.dolby.com/s/article/Dolby-Vision-for-video-sharing-services-FAQs?language=enUS)。基层输出仍是 HDR 视频，普通 SDR 屏幕可能需要播放器色调映射。
