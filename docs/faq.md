# 常见问题

[文档目录](README.md) · [使用指南](usage.md)

## 下载、启动和设置

**下载哪一个，源码 ZIP 能直接运行吗？** 普通 Windows 用户选择 `*-setup.exe` 安装包；便携使用选择完整 ZIP，完整解压后运行 `hamster-toolbox-desktop.exe`。需要控制台时用 `hamster-toolbox.exe` / `start-toolbox.cmd`。源码包不含预编译程序和组件，更新 ZIP 不含 `tools`，都不能当作完整版直接使用。Linux/macOS 见[平台说明](platforms.md)。

**能开机自启和检查更新吗？** 安装时或“通用设置 → 启动”可启用当前用户登录自启，默认关闭；登录后静默进入托盘。工具箱页面底部“关于与更新”显示当前版本、构建时间和最新正式版，支持手动检查；发布按钮始终打开版本列表，不自动下载安装。开发版不会因公开正式版较旧而提示降级，网络失败会显示检查失败，见[安装说明](installation.md)。

**刷新或关闭浏览器会停止任务吗？** 已提交的批处理在后台服务继续执行，刷新后重新读取状态。关闭控制台或结束服务会中断任务，已完成操作保留。[任务历史](task-history.md)可载入参数；图片/视频压缩、元数据清理与视频缩略图可只重新预览失败和未完成文件，再确认执行，单个文件从头处理。上传、浏览器播放和网页悬浮窗口依赖当前页面；上传可重新选择相同文件接续断点，播放器与悬浮窗口不能跨刷新保留。mpv 原生窗口独立运行。

**管理端口为什么会变？** 默认自动分配；以启动终端显示的链接为准。可用 `start-toolbox.cmd -port 8790` 固定，端口占用会提示失败。共享另用保存的端口，默认 `18788`；其他设备使用共享地址，不能分享带 `session` 的本机管理链接。

新安装默认共享端口为 `18788`，已有用户继续使用已保存端口，不自动迁移或改变穿透配置。端口无法保证永不被其他程序占用，发生冲突时仍需更换并同步代理。

**刚启动为什么共享端口就被占用？** 其他程序的对外连接也可能占用同一个本地端口，不一定有监听服务。Windows 可用 `Get-NetTCPConnection -LocalPort 18788` 或 `netstat -ano` 查看全部连接状态，再根据进程号识别程序；只筛选 `Listen`/`LISTENING` 可能漏掉占用。若提示系统拒绝，还可能是排除端口或权限策略，可用 `netsh interface ipv4 show excludedportrange protocol=tcp` 查看。优先更换共享端口后重试，不必结束显卡或系统服务；已有穿透/代理的转发目标也需同步修改。工具箱不会自动换共享端口，以免保存的访问地址失效。

**设置保存在哪里？** 默认在当前用户配置目录的 `media-toolbox` 下，Windows 通常为 `%APPDATA%\media-toolbox`；启动终端显示实际位置，`-data` 可更改。快速访问保存到服务端，开启“重启后恢复本机资源标签页”时，目录标签可保存到服务端，前进后退历史仍属于浏览器会话。不要把私人设置放进源码或发布包。

## 批处理

**`.001/.002` 分卷识别不到，要补 `.7z` 吗？** 当前版本会读取首卷文件头，识别去掉格式后缀的 7z/ZIP/RAR 字节分卷；无需手动合并或改名。所有分卷放在同一目录，只把首卷列为一个任务。文件清单加密时要先填写解压密码再扫描，见[解压规则](usage.md#解压资源)。

**大压缩包解压时能看到进度吗？** “任务状态”同时显示已完成的总包数和当前包的实时阶段。解压、检查结果、写入输出、可选原包清理分别显示，无法计算时显示“进行中”；剩余时间是本阶段估算，解压接近 100% 仍需等待检查与写出。

**生成视频拼图为什么提示找不到 `frame.png`？** FFmpeg 可能成功退出但没有输出画面，尤其是错误标为 `.mp4` 的 MPEG-TS 或缺少定位索引的片尾。当前版本会自动进行兼容定位，保持截取时间并清除旧临时帧；仍失败时提示检查视频。更新后可在任务历史中重扫失败与未完成项，已成功输出不会覆盖。

**为什么扫描后没有处理？** 扫描仅预览；点击“执行预览结果”或 CLI 添加 `--execute` 才执行。冲突项会跳过；预览筛选只影响显示范围。参数或源内容改变后需要重新扫描。

**图片会重复压缩吗？** 普通扫描不按历史永久排除源文件。已有同名输出时跳过；手动将结果覆盖回源文件后，仍可能再次压缩。任务历史的定向重扫只选择该记录中的失败和未完成项；日常仍可用格式筛选或分开待处理目录避免重复，有损编码多次执行可能累积画质损失。

**PNG 无损压缩为什么没有变小很多？** 无损优化不能保证照片大幅缩小。可以选高画质 WebP，保留 `.png` 名称或改为 `.webp`；保留后缀时实际仍为 WebP，部分软件可能不兼容。分辨率不变不代表无损，先抽查。[完整说明](usage.md#png-编码方案)

**显卡一定压得更小、更清楚吗？** 硬件编码主要提供速度和较低 CPU 占用，大小与画质取决于内容和编码参数。参考[视频模式](video-compression.md)先做小样本比较。压缩编码与 mpv 播放的硬件解码是不同功能。

**清理元数据能去视频广告吗？** 只清理支持的标签、描述等信息，不去除画面水印、片头或音轨广告。图片方向和色彩标签移除后可能影响显示，应检查输出副本。

**删除进入哪台电脑的回收站？** 文件所在的工具箱主机。默认回收站/废纸篓，不可用则报错保留，不自动永久删除；永久删除需另选。外部去重软件的删除行为由其自身控制。

## 浏览、播放和共享

**输入共享口令后还停在登录页？** 当前版本已修复首次访问时必需脚本被认证拦住的问题，正确口令后应直接进入。使用旧版或早期测试包时，更新服务端后重新打开共享地址。若提示登录状态未保存，允许本站 Cookie 后再试；若提示页面加载失败，按显示的原因排查，不必反复刷新。

**缩略图或时长为什么暂时没有？** 封面与时长按需读取，大目录先显示列表，再补齐信息；最多 2 个并发时长探测，失败显示“未知”。检查组件、加密或损坏文件等原因，见[媒体预览](media-preview.md)。

**视频进度怎么只有几秒？** 兼容播放的原生进度可能只代表缓冲片段，使用画面下方“全片进度”查看全长和跳转。预览不修改原件；本机多路视频可用 mpv，实际硬解状态在“原生播放器”查看。

**为什么根目录不能批处理，却能浏览或共享？** 批处理会改名或写输出，必须选择具体资源子目录。资源管理器允许浏览/共享根目录，系统、工具箱和数据目录仍受保护，浏览入口不等于所有内容都允许修改。

**手机在外能连吗？** 可以用 xEdge 或 ZeroTier 将电脑和手机接入同一个虚拟网络，再用手机浏览器打开电脑的组网 IP 与共享端口，见[新手分步教程](remote-access-quickstart.md)。电脑与工具箱需保持运行；使用其他穿透或 HTTPS 域名时见[通用配置](remote-access.md)。访客不能启动主机的 mpv 或其他应用。

反馈问题时附版本、复现步骤及脱敏日志，不公开会话链接、密码或私人路径。

**视频报 Non-monotonic DTS，换显卡或 CPU 都失败？** 可变帧率视频的帧时间可能细于编码器默认时间基准，舍入后会出现重复时间戳。压缩和导出命令会保留可读取的源时间基准；不强制改成固定帧率，不通过降低尺寸绕开。真正损坏的时间轴仍可能报错，原件保留。HDR 按所选策略处理；不支持的动态 HDR 和主动取消属于其他状态。

若同一错误前面显示 `aost.../copy`，则是音轨复制时间戳异常，换视频编码器通常不能解决。工具箱会在当前编码器上重试 AAC，并对明确的音轨时间戳倒退启用衔接补偿；正常音轨仍优先直接复制。修复会重编码音频，异常位置可能补静音或去掉重叠部分，建议抽听；原视频保留。
